## How to read this list

Each row gives you four things:

| Column | Meaning |
|---|---|
| **Project** | Name, link, and a small badge: `OSS · MIT` (open source + licence), `SaaS`, `Spec`, `Paper`, `Guide`, `Data`, `Model`. Topic tags follow the badge where useful. |
| **What it does** | One line, written for people who already know what an LLM is. |
| **Stars** | Live GitHub star count read from the GitHub API — a rough popularity proxy, not a quality score. `—` means the project isn't on GitHub. |
| **Release** | Latest release/tag, npm or PyPI version, or a status note. ⚠️ flags archived projects and dead links. |

**Selection rule:** a project earns a place if people are *actually using it* — measured by
stars, download counts, release cadence, adoption in other projects, or because it defines a
standard the ecosystem has to interoperate with. Stale projects are either dropped or marked
⚠️ archived. Star counts are refreshed by a scheduled workflow, so the numbers never rot.

**A note on "agents".** The word is used three ways in 2026, and this list keeps them apart:

1. **Agentic applications** — a model in a loop with tools and a goal (most of categories 4–17).
2. **Agent frameworks/SDKs** — the programming model you build such applications with.
3. **Agent protocols** — the wire formats that let independently-built agents and tools talk
   to each other (MCP, A2A, AP2, AGNTCY, …).
